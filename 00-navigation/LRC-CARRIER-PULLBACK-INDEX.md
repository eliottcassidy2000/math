# LRC Carrier Pullback Index

**Purpose:** a large, operational pull-from / contribute-to index for agents
trying new LRC14 proof carriers.  The existing `LTI-*`, `LTT-*`, and `LTM-*`
indexes store technique handles.  This file asks the next practical question:
when an old tournament, metagraph, series, sieve, automaton, topology, or
cross-domain trick is pulled back to LRC, which packet fields must travel with
it, what does it preserve, and what should another agent do next?

**Claimed handles:** T1108, LTI-175, LTT-073.

## How To Use This File

1. Choose one row whose source tools match the proof route you want to try.
2. Copy the retained fields into the packet manifest or script output before
   computing a scalar quotient.
3. Run a fiber-mixing audit on boundary/open status and theorem route.
4. Record Tournament Analysis data whenever the row creates a finite carrier
   tournament: vertex set, pairwise observable, switch/gauge, tie path, score
   histogram, SCCs, directed cycles, edge flips, and Hamiltonian-path count.
5. If the row fails, add the failure as a guardrail.  Do not delete the row.

## Tournament Analysis Setup

Primary vertices are proof-carrier pullbacks, not runners.  Secondary vertex
sets may be runners, gaps, fixed circle sections, section boundaries,
wall-crossing events, residues, cover arcs, Fourier modes, Haar rectangles,
matroid circuits, p-adic roots, automaton states, packet labels, or proof
obligations, but the row must say which LRC predicate survives the quotient.

Pairwise observable:

```text
boundary/open status retention
theorem-route retention
exact scale retention
endpoint/topology retention
arithmetic/period retention
harmonic certificate retention
state-lift/residual routing
family-transfer potential
formal/checkable payload
proof cost
```

Switch/gauge: orient one carrier over another when it retains strictly more of
the active proof payload without increasing unnamed residual debt.  If tied,
use this Hamiltonian tie path:

```text
packet_sheaf > endpoint_topology > harmonic_certificate > arithmetic_period >
automaton_language > tournament_metagraph > analytic_smoothing >
state_lift_geometry > computation_formal_forum
```

## Challenged Assumption

The challenged assumption is that the next creative LRC proof should start by
choosing runners as tournament vertices or by searching for one decisive
scalar.  This index treats the proof carriers themselves as vertices.  Runner,
sequence, series, and metagraph data become admissible only after the row names
the retained LRC predicate, the destroyed information, and the certificate or
residual sector that pays for the loss.
