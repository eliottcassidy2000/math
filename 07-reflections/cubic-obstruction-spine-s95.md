# Cubic Obstruction Spine S95

This session added one more cubic-looking object to a repo that already had
several of them.

The new object is the endpoint SC collision:

```text
three merged parent nodes  ->  one non-private SC child column
```

Through `6->7`, every non-private SC endpoint column has support exactly `3`,
and those columns are independent over `F_2`.

This resembles older threads:

- directed 3-cycles are the first non-transitive tournament obstruction;
- `beta_3` is the first higher path-homology obstruction;
- Krawtchouk `B_3` is the first skew/twist coordinate after `H` and `c3`;
- OCF/independence-polynomial channels activate in steps controlled by
  disjoint 3-cycle packings.

The careful version of the meta-hypothesis is not "these are the same object."
They live in different complexes and quotient maps. The claim is weaker and
more useful:

```text
when a tournament quotient stops being linearly/triangularly controlled,
the first stable obstruction tends to be a ternary relation.
```

Endpoint transfer now gives a concrete boundary-rank instance of this slogan.
The next test is to determine whether each support-3 collision is generated by
a canonical directed triangle in the endpoint-deletion shadow, or whether
"three" is only an incidence-rank phenomenon with no literal 3-cycle witness.

## S95 Geometry Update

`endpoint_collision_geometry_s95.py` answered the first naive version: the
support-3 collision is not generally a triangle in the parent merged metagraph.
At `6->7`, the induced edge counts among the three owner nodes are
`{0:1,1:6,2:5,3:2}`.  The cubic residual is therefore an endpoint-incidence
hyperedge, not ordinary clique geometry.  See
`endpoint-collisions-as-incidence-not-adjacency-s95.md`.

The same update found a cleaner proof target than the triangle guess: the
collision hypergraph leaf-peels completely through `6->7`.  So "cubic
obstruction" here may mean a peelable ternary boundary relation, not a literal
cycle.
