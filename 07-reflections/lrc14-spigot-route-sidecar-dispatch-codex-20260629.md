# LRC14 Spigot Route-Sidecar Dispatch Reflection

The spigot prompt was useful because it separated "emit a certificate" from
"remember everything."  A spigot-style terminal proof should keep only bounded
carry state, emit the next certificate, and never fall back to row names.  In
the current LRC14 packet that carry is not the private bit; it is route sidecar
`R`.

The finite check is stronger than the earlier summary.  `I` and `Q` are pure
for both private-firewall status and private/dead/nondead status, but they
still mix the HYP-3490 route.  Even `K,N,T,S,F,C,M,A,I,Q` mixes one route
fiber over seven rows.  So the row-free multiplicity-one incidence-cut lemma
can close the private predicate, but it cannot by itself tell the terminal
proof whether it is in the six singleton-current rows, random031, AP84, or
ordinary currented terrain.

The proof interface should therefore be explicit:

```text
I/Q incidence cut supplies private status.
R supplies terminal route unless a reconstruction theorem is proved.
HYP-3521 emits the terminal certificate.
HYP-3522 supplies the owner carry for the pure bypass.
```

The concurrent HYP-3523 certificate spigot, HYP-3524 hydrotope scout, and
HYP-3525 guarded-emission atlas make this sharper.  They explain how random031
emits certificates, how the owner tail is scheduled, and how a general
holdback lemma should look.  HYP-3526 explains the concrete thing their stream
still must not forget: route sidecar `R`.

That is a cleaner target than a row exception list.  It also keeps future work
honest: deleting `R` is allowed only after a named route-reconstruction theorem
replaces it.
