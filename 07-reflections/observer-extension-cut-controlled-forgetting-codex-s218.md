# Observer-Extension Cut Payload As Controlled Forgetting

The A000568 perspective defect is useful because it is small enough to expose
the general shape.  Rooted node memory saturates, but adding one observer still
has extra payload.  That payload is not "more neighborhood"; it is the cut
between the old object and the new outside interaction.

The same thing keeps happening in the LRC14 stack.  A quotient works inside
one view, then fails when asked to pass through the next operation:

```text
rooted tournament -> add observer
coarse endpoint word -> transfer owner
automatic word -> preserve route
row/column Haar margins -> push fixed-margin switch
coarse ET/Hensel status gate -> schedule routes
compact topology -> distinguish residual teeth
pair-good count -> explain generator
```

So the abstraction is: every quotient has an outside boundary.  The
observer-extension payload is the coordinate on that boundary.

This changes the working order.  Do not start by asking how many bad objects
remain.  Ask what operation makes them bad.  The operation names the payload:

- adding a tournament vertex names an incident word or sector deck;
- deleting/unrooting names a deletion-parent fiber;
- crossing a capacitor names a first cut and zeta/owner exit;
- folding a pair-good decoy names a blocker tooth and active owner;
- compressing a layer sheet names rectangle and hourglass defects;
- pushing an analytic or automaton shadow names the blindness/magnitude
  cocycle it forgot.

The pay-off is that counts can stop being scary.  Pair-good decoys are not a
mass to bound first; they are generated by modular blocker teeth.  Residual
capacitors are not anonymous mixed pairs; they are two-plate cut obligations.
The `k^2+k` diagonal-layer lines are not independent data; they are a
coboundary with cycle defects.  The observer-extension language lets all three
sit in the same controlled-forgetting rule.

For future work, the right manifest field is not just `destroyed_coordinate`.
It should be:

```text
quotient
next_operation
observer_extension_payload
discharge_rule
```

The discharge rule has the familiar list: retain it, reconstruct it, kill it
by dual/cocycle/cut, descend it familywise, stop at AP/GW boundary topology, or
name residual debt.  Anything else is uncontrolled forgetting.

This also makes Tournament Analysis less arbitrary.  The vertices should be
the payloads that can make a quotient legal: endpoint-owner packets,
sidecar-observability columns, capacitor cuts, rectangle defects, sector
decks, closed-H1 owner supports, primitive decks, blocker teeth, and only then
raw scalar shadows.  Runners are one possible vertex set, but for LRC14 they
are usually too early in the pipeline.
