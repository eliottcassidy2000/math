# LRC14 Wide Address Repair - Codex S55

The useful hidden gem from the old owner-private and compatibility-wall work is
real, but it is not quite the first version of the idea.  Exact private-sector
ownership is a deletion derivative, and it is informative, but when paired with
enough residue data it becomes too close to a row identifier.  That is useful
for debugging a finite atlas, not for proving a lemma.

The non-overfit object in the exact scout is coarser: the measured missed-state
word before scalarization.  In the `513` row audit bank, scalar span data and
private mass both leave `3` high/low mixed buckets, additive leaves `1`, but
coarse `state_mass` leaves `0` while still compressing to `286/513` buckets.
This says the direct-risk structure is controlled by how many missed-sector
states occur, how evenly their wall mass is distributed, and the first few
missed-count masses `p1,p2,p3`.

The challenged assumption was that tournament vertices should be runners,
arcs, or even rows.  Here the useful vertices are proof channels:

```text
residue_private > state_mass > additive > private_mass > scalar
```

with overfit channels penalized.  The quotient preserves the HYP-2675 predicate
`p0(E)<=cap_k` for true-wide rows; it destroys the exact wall word, exact
runner identity, and exact deletion owner map.  That loss is acceptable only if
one can prove a state-mass deficit lemma.

The proof route I now believe is:

```text
finite low-height compatibility packets
  + state-mass entropy/support deficit
  + Weyl/decorrelation error to Q(k-1)
  => true-wide p0(E) <= cap_k.
```

This also explains why the older unrelated support-gate and state-word sessions
kept reappearing.  They were all warning against scalarizing too early.  The
LRC14 true-wide branch likely needs a short finite address ledger first, then a
genuine analytic tail bound only after the proof state has been sorted.  The
concurrent HYP-2684 BV/Fourier route is exactly that tail-bound target: it
separates nonresonant scale decorrelation from the low-height resonant rows that
this address ledger is meant to classify.
