## 5. Mod19 builds actual recursive routes, with a sharp four-step bound

The [nineteen-ray theorem](mod19_route_lifts_20261004.md) proves:

> Every residue modulo every19^a contains infinitely many positive odd
> sources with an explicit first-hit route to1 of at most four odd steps.
> Four is the smallest possible uniform bound.

Eighteen rays are predecessors of1 or5. The exceptional residue is
`6=-1/3 mod19`; it needs the internal-exponent family

\[
 n_t=\frac{53\,2^{8+18t}-5}{9},\qquad
 \text{word }(1,7+18t,5,4).
\]

Its first route is `1507 ->2261 ->53 ->5 ->1`. A complete six-case modular
proof excludes odd ranks at most three in this residue. For every ray,

\[
 v_{19}(n_t-n_u)=1+v_{19}(t-u).
\]

Each next source digit therefore selects one next parameter digit. The
compiler answers arbitrary finite19-adic address requests without expanding
the source. At precision80 its parameter has336 bits while the constructed
source exceeds10^100 binary digits.

This bank contains only `(19/18)log_2 X+O(1)` sources below X. It has full
19-adic support and natural density zero. Asking for the residue of19 returns
87381, which has its own checked route; that is not a certificate for19.
An exact match to the supplied integer is still required.

The selector package implements that check as `lookup_ray_certificate(n)`.
It uses `n mod19` to choose a candidate ray, then verifies the integer identity
`Dn+B=A*2^(18t)` with a nonnegative integer t. Only a successful exact match
returns the ray's completed AST. The optional helper is excluded from the
policy-comparison tables;190 members and190 same-residue nonmembers were
checked separately.

There is a useful derived observation. Both the bank and its complement in
the positive odd integers meet every19-adic residue class: the bank does by
the theorem; the complement does because each odd residue progression has
positive natural density while the bank has density zero. Consequently no
procedure seeing only finitely many19-adic digits, even adaptively, can
decide exact membership in this bank on every source. The terminating
procedure must retain another coordinate, such as the integer itself or a
height bound. An end-of-expansion marker would already supply extra height
information and is not part of that digit-only interface. This concerns
bank membership, not the Collatz conjecture.

## 6. Why19 is the first shared ternary digit, and how the hierarchy continues

In an inherited inverse row,

\[
 n_b=(2^{\kappa+6b}u-1)/3.
\]

The ternary address constrains `b mod3^(a-1)`. For a19-adic unit hub, the
19-adic address constrains `b mod(3*19^(k-1))`. These constraints share the
same block index. For a>=2 they are compatible exactly when their residues
agree modulo3; at a=1 there is no shared-digit obstruction. The two source
moduli are coprime, but the parameter clocks need not be.
The [joint address selector](mod19_recursive_observers_20261004.md) proves the
exact condition, handles nonunit hubs, and returns a completed child of the
supplied certified parent.

For an odd prime p different from3, set

\[
 d_p=\operatorname{ord}_p(2),\qquad
 R(p)=\max(0,v_3(d_p)-1).
\]

The six-exponent block has order `d_p/gcd(d_p,6)`. At noncollapsed p-adic
precision, the shared part of its clock with `3^(a-1)` is exactly

\[
 \boxed{3^{\min(a-1,R(p))}.}
\]

Thus R(p) counts shared ternary digits. It remains unchanged when p-adic
precision increases: an order lift can add powers of p, not powers of3.
Nineteen is the first possible prime with R(p)>0, since this requires
`9|ord_p(2)`, hence `9|p-1`, and19 has order18.

| Prime | Order of2 | Order of64 | Shared ternary depth R(p) |
|---:|---:|---:|---:|
|19|18|3|1|
|87211|54|9|2|
|5779|5778|963|2|

This supplies the promised recursive connection to the earlier missing
cyclotomic factors. Put

\[
 C_r=\frac{2^{2\cdot3^{r-1}}-2^{3^{r-1}}+1}{3}.
\]

The first values are `C_1=1,C_2=19,C_3=87211`. For r>=2, every prime
divisor p of C_r has order `2*3^r`, so R(p)=r-1. Each level therefore
introduces one more shared ternary digit. The proof does not assume C_r
is prime. The first empty levelC_1=1 is the same primitive-factor exception
seen at `2^6-1=63`.

required. Their shared-depth invariant nevertheless agrees: both retain

in `ord_5779(64)=9*107` is retained separately. This is an exact common
invariant, not renewed equality of the two prime sequences. Proofs and
