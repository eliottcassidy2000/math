## 3. Exact certificate substitution

Let \(U(n)=(3n+1)/2^{v_2(3n+1)}\) on positive odd integers.
A supplied receipt is
\[
(n,h,u,v),\qquad U^u(n)=U^v(h),
\]
where the notation includes every exact valuation in the tuples \(u,v\).
Both words are independently replayed, with no operation allowed after
visiting ROOT. Suppose the parent's supplied first-hit ROOT word is \(w_h\).
Determinism forces \(v\) to be its literal prefix; the implementation checks
this explicitly. Then
\[
w_n=u\;\Vert\;w_h[|v|:]
\]
is a first-hit ROOT word for \(n\).

Indeed, the remaining suffix starts at the verified common endpoint. Neither
supplied prefix has an internal ROOT visit. If the endpoint is ROOT, the
suffix is empty. Otherwise the parent's strict suffix reaches it for the
first time. The complete exported word is replayed independently as well.
No child convergence is inferred from a common endpoint alone.

`audit_program` authenticates all receipts, exact integer labels and exact
string keys, complete unique build order, named source matching, and parent
precedence. The only unconditional recipe is the empty word at source 1.
A circular set of dependencies fails this DAG interface even if its local
common-future statements are true. A separate periodicity/holonomy
certificate would be a different proof object.

`execute` then checks each physical event against the retained program.
It refuses a missing parent payload, overwrite of a live slot, incorrect
source binding, early release, omitted output, duplicate build, malformed
slot, or false valuation. Output hashes are comparison metadata, never
substitutes for words or recipes.
The output metadata's `cost` field is the valuation sum; adding the odd-word
length gives the unaccelerated Collatz step count.

## 4. Fixed-schedule liveness theorem

Fix a valid topological build order. Each requested output may be emitted
immediately when built. For node \(v\), let \(b(v)\) be its build index and
\[
d(v)=\max\bigl(\{b(v)\}\cup
 \{b(z):z\text{ directly consumes }v\}\bigr).
\]
The resource model retains one indivisible immutable word payload per live
node, forbids recomputation, and allocates each output payload before
releasing its consumed input. The immutable recipe, verification workspace,
and external emitted-output sink are outside this metric.

Under this model the minimum peak slot count **for this build order** is
\[
M=\max_i\#\{v:b(v)\le i\le d(v)\}.
\]
The closed endpoints matter: at a consumer's build, its last-use input and
new result are simultaneously live.

For the lower bound, every displayed interval crossing \(i\) represents a
payload already built and still needed at that instant. For attainment,
release a payload immediately after its last consumer/output and always
reuse the lowest free slot. This is the standard interval-liveness argument;
no novelty claim is made. If payload \(v\) is charged a fixed weight \(s(v)\),
the same proof gives \(\max_i\sum_{b(v)\le i\le d(v)}s(v)\).
The code uses \(s(v)=1+|w_v|\), an abstract word-cell count.

This does not minimize over all possible topological orders, recomputation
strategies, compressed word representations, or in-place implementations.
It also does not measure Python memory: integer bit sizes, tuple-copy
transients, verification buffers, program storage, and retained output
certificates require separate accounting.

The key distinction is between **releasing a working payload** and
**discarding a proof obligation**. A future additional consumer requires a
new schedule, and possibly reconstruction from the retained program. The
old schedule does not authorize using a released slot as if its old word
were still present.
