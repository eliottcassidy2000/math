# Checkpoint-two verification and provenance scope

This additive checkpoint retains every checkpoint-one byte and mode, including
its old guide and tooling, and adds frozen native research, independent audits,
explicit final-wording review, complete C2 inventories and a current guide.
The latest file manifest lists the complete packet; its native-copy ledger
includes C1 and C2 native files. No compiled binaries are curated.

Fifteen approved replay jobs cover the inherited decoder, six-move producer
and independent score audit, temporary C++ forest enumeration, bracket formula,
root arithmetic/marked-Paley/palette checks, producer and independent golden
checks, return-loss, fifteen-move producer/auditor, and CRT producer/auditor.
Every job is replayed normally and under Python `-O`, with receipts compared
byte-for-byte and frozen inputs/modes rechecked afterward. Source snapshots
are inert except the explicit inherited decoder. Finder C++ sources and native
shell recipes are retained as provenance, not executable replay entry points.

All-size claims rely on the separately audited proofs. Bounded enumerations
remain FINITE-EXACT. Exact source snapshots bind to source commit, repository
path, Git blob, SHA256, byte size and mode. Dependency-only readbacks and the
historical MISTAKE-584 excerpt have separate declared scopes; a local portable
hash check is not a fresh read of remote Git. Native audit receipts remain
unchanged when later status wording is promoted; separate final-review records
close that final-byte provenance gap instead of relabelling old hashes.

Documentation checks are targeted: startup budgets/sentinels/truth tokens and
current status fixtures, explicit changed canonical frontmatter, bounded routes,
local Markdown destinations, and unchanged hypothesis clauses. They do not
claim full-corpus dependency validation, full-repository materialization, a
Lean proof, or external-link availability. Startup surface caps are unchanged.

This checkpoint is assembled OFFLINE at C1's local commit. Publication belongs
to the separate publication owner, after C1 is verified remotely. The owner
must inspect incoming changes, semantically integrate exact-substring index
updates, rerun affected gates, publish non-forced and verify exact remote
commit/tree/parents/blobs, ancestry and final local 0/0. CI is not claimed by
these local receipts; empty CI observations never establish a passing state.
