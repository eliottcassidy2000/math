## 1. Object and inheritance

Let G_n be the simple undirected graph on {1,...,n}, with a--b an edge iff
a != b and a+b is an integer square. A cycle has at least three vertices.
A normalized **original nice pair** at n consists of Hamiltonian paths P_n
and P_(n+1), both starting at1, ending at3 for odd order and8 for even order,
and putting each shared label in positions of the same parity. Positions
start at1. This is the original Gerbicz invariant recovered in
[Session124 reconstruction](../../session124_gerbicz_reconstruction_20261031/GERBICZ_RECONSTRUCTION.md), not the
later protected B-seed family with an odd endpoint10.

Closest inherited mechanism: the Session32 endpoint-aware ear correspondence
and forced-chain obstruction at31. Hostile example: minimum degree two permits
a spanning2-factor without a Hamiltonian cycle. Corrected near miss: adding a
vertex to the *graph* need not preserve a particular spanning cycle. Useful
sidecar: the label-by-label positional coloring, not merely the two orders.
The live comparison board is graph inclusion / cycle edits / endpoint ports /
shared phase / hidden chain constraints.

If 32 is declared the new origin, k maps to G_(32+k), for k>=0. This gives a
perfectly precise successor on the underlying nested graphs. A successor on
chosen Hamiltonian certificates needs extra structure; the first step already
shows why. Nothing here claims all consecutive cycles form a nice pair, or
that arbitrary Hamiltonian cycles can be transported without rewiring.

## 3. Exact insertion criterion and the local rigidity of1,3,8

**PROVED:** inserting a new largest vertex v into an old edge a--b is possible
iff all three sums a+b,a+v,b+v are squares and a--b is actually an edge of the
chosen old cycle. The first three conditions only give an *arithmetic candidate*;
they do not establish occurrence in a Hamiltonian cycle.

With a<b<v, write a+b=r^2, a+v=s^2, b+v=t^2. The complete parametrization is

```
a = (r^2+s^2-t^2)/2,
b = (r^2+t^2-s^2)/2,
v = (s^2+t^2-r^2)/2,
```

where positive integers r<s<t satisfy t^2<r^2+s^2 and r^2+s^2+t^2 is even.
These conditions are necessary and sufficient for distinct positive integers
0<a<b<v with the three square-sum edges. They follow by solving the three
linear equations; their inequalities give exactly positivity and ordering.

**FINITE-EXACT arithmetic consequence:** no arrival v in33..43 has an insertion
candidate. The first after the32-origin is v=44, with a=5,b=20 and roots5,7,8.
This candidate really occurs in a Hamiltonian cycle: the following G43 cycle
contains5--20, and replacing that edge by5--44--20 gives a G44 cycle.

```
1,15,21,43,38,26,10,6,19,30,34,2,7,18,31,5,20,29,35,14,11,25,
39,42,22,3,33,16,9,27,37,12,4,32,17,8,28,36,13,23,41,40,24,(1).
```

Thus43->44 is the first post-origin pure-insertion step that is actually
realizable, not merely the first arithmetic candidate. Both witnesses are
checked directly; no claim that every G43 cycle has this edge is needed.
So even the first nice pair,41/42, cannot be a pure edge insertion. The checker
compares direct integer-square enumeration against the root parametrization
for every v<=100; this is not an all-order density or persistence claim.

There is a stronger all-order fact about the requested triple. In the infinite
simple square-sum graph,

```
N(1) intersection N(3) = empty,
N(1) intersection N(8) = empty,
N(3) intersection N(8) = {1}.
```

For the first identity, squares would differ by2, impossible by factoring the
difference of squares. Difference7 forces roots3,4 and candidate vertex8,
which is not a common neighbor in the *simple* graph because8--8 is excluded.
Difference5 forces roots2,3 and vertex1. Meanwhile1+3=4,1+8=9,3+8=11: the
triple is an induced fork centered at1, not a triangle. In particular neither
closing edge1--3 nor1--8 can ever be subdivided by a fresh positive label.

## 4. Why the nice-pair invariant is positional, not numerical

Put c_P(x)=1 if label x occurs in an odd position of P, and0 otherwise. The
normalizations force c(1)=c(3)=1 and c(8)=0 in both members of any nice pair.
The length parity changes, but shared-label colors do not. Counting odd slots
forces the new label n+1 to have position parity n+1: if n is odd it is in an
even position, and if n is even it is in an odd position. This conclusion is
about the *new label only*, not a claim that all labels have their numerical
parity as their position parity.

Let S_n be the set of odd-position label subsets among normalized order-n
paths satisfying these three port colors. A nice pair exists iff a member of
S_n is the restriction to[1,n] of a member of S_(n+1). This is an exact
existence criterion. A spectrum forgets the actual ordering and multiplicity;
one witness per shared subset repairs existence, and multiplicities recover
how many normalized path pairs realize it. Generic cycle existence forgets
far too much to decide this compatibility.
