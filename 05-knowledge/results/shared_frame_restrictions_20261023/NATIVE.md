# An exact consumer of the attachment compiler: native path partners

23 October 2026. **PROVED scoped:** equivariance, converse transport and
guarded lift counting. **FINITE-EXACT:** one actual strongly connected
18-vertex source with 27 compatible cell charts. This supplies a native
interface and a hostile kernel example, not a complete all-size port bank.

## 1. Transport the source and the partner, not merely their statistics

For a tournament T and an actual directed Hamiltonian path P, let K_P(T)
retain the arcs of P and reverse every other arc. This is again a tournament,
contains the same P, and K_P(K_P(T))=T. If f:T->T' is an actual tournament
isomorphism, then

    f(K_P(T)) = K_(fP)(T').                              (1)

The proof checks each unordered vertex pair: membership among the path
arcs is transported exactly by f. Also

    K_(reverse P)(T^op) = K_P(T)^op.                     (2)

Thus a compatible shared-frame transporter from the earlier
[lattice compiler](../cyclic_attachment_lattices_20261023/README.md)
has a precise native consumer. Retain (T,P,K_P(T),f), the actual indexed
endpoint owners, and the converse flag. Every lift supplies a witnessed
native partner. No statistic-only comparison is substituted for (1).

This is elementary equivariance of an inherited native operation, not a
new definition of the tournament metagraph. Source automorphisms transport
one path to its orbit; they need not generate every Hamiltonian path or
every native partner class. Completeness across different path orbits is
an additional obligation.

## 2. Nonfunctional cyclic kernels occur on actual Hamiltonian ports

Use two named consecutive circulant nine-tournaments: within each cell,
u->v iff v-u belongs to {1,2,3,4} modulo 9. Orient a cross pair from cell
0 to cell 1 iff u=v modulo 3. The supplied internal chart groups are C9
translations. The actual cross-block self-comparison relation is

    R={(a,b) in C9 x C9 : a=b mod3},                      (3)

with 27 elements. This is exactly a lattice relation from the prior compiler,
with basis (3,0),(1,1), common quotient C3 and kernel C3 x C3. We make no
claim here that cell-swapping isomorphisms are included in this supplied
cell-preserving chart language.

There is an actual Hamiltonian path: visit 0,1,...,8 in the first cell,
then 2,3,...,8,0,1 in the second. The crossing 8->2 uses the specified
matching-residue arc. Every (a,b) in (3) transports this path and its
partner by (1). The resulting 27 indexed paths have 27 different endpoint
pairs (a,1+b), with cell names retained. Only three quotient frames exist,
so collapsing each kernel loses nine actual port lifts.

Fixing the first endpoint leaves three second-endpoint lifts. Fixing both
leaves one. The source is strongly connected: each circulant cell is
strongly connected, and cross arcs occur in both directions. The checker
also verifies this independently by reachability from every vertex.

The simultaneous unit shift (1,1) returns to quotient state zero after
three applications but reaches (3,3), a nonidentity kernel lift. Both
endpoints have moved. This is the concrete carry from
[CARRIES.md](../cyclic_attachment_lattices_20261023/CARRIES.md), now retained
through the actual native partner/converse square.

## 3. Exact guards must be evaluated on their stated domain

Let S be a finite set of compatible full lifts, q:S->Q a quotient, w(s)>0
the retained source multiplicity, and gamma:S->{0,1} a supplied exact guard.
The accepted quotient mass is

    W_gamma(q)=sum_(s:q(s)=q) w(s) gamma(s).              (4)

If every fibre has k equally weighted lifts, replacing (4) by k times
the value on one representative is valid for **all representative choices**
iff gamma is constant on every fibre. Otherwise the guard requires its
kernel-conditioned histogram. This equivalence is immediate by choosing
two representatives with different guard values. It remains valid for a
vector of port observations and for separate converse branches.

The finite adapter in `native.py` retains complete records and evaluates a
supplied guard on each one, with positive integer source multiplicities.
A weighted control agrees with literal repeated copies of the source.
It uses no independence assumption and does
not promise compact enumeration for an implicitly enormous kernel.

For a deliberately transparent hostile, take the **synthetic** integer
port clock L(a,b)=least(a)+2 least(b), and accept L=0 mod8. It is not a
homomorphism on C9 x C9: changing a representative by 9 changes its residue
mod8. The retained least representatives make it a well-defined finite
table. The three quotient fibres have nonconstant guard histograms;
choosing the section a=b in {0,1,2} and multiplying its accepted mass by
nine gives the wrong answer. The full adapter and a direct congruence join
agree. Exact values are in `native_receipt.json`.

This clock is NOT the repository's electrical mod-8 invariant. The inherited
electrical certificate is
`05-knowledge/results/metagraph_hall_bott_20261023/receipt.json`;
its immutable source hash is recorded in our manifest. We leave its
carrier unchanged. Applying (4) to it requires an actual table on the
new native records or a proved transport law; neither is inferred merely
because both moduli are 8.

## 4. The next meaningful compiler obligation

For one supplied source and candidate partner, the exact lattice/Mal'tsev
transporter is already available. The remaining task is to construct a
small complete set of **path orbits** and their actual shared-port effects,
or prove that a proposed smaller inventory has identical future native
attachments. A complete automorphism bank of one path is not such a proof.

The restricted coupling theorem suggests preserving observer cuts while
resampling inside blocks. To turn it into native wiring progress, every
auxiliary transition needs a sequence of legal native moves with the same
boundary records and a controlled multiplicity/congestion. Our fixed-path
absorbing state shows why this cannot be asserted from the auxiliary 8/9
gap alone. Components and guards belong in the comparison theorem.
