# Prepublication replay provenance repair

The first direct-permutation order-nine attempt exceeded its resource target.
Interrupting its command wrapper did not reliably stop the child Python
process. That old process later wrote its degree-canonical bank over the newer
refinement-canonical bank. Both computations returned the same class counts,
but their canonical codes and birth records differed. The normal/optimized
byte comparison detected the overwrite before this packet was frozen.

The original producer hashed its source file at the end of the run. Because
the file had changed while the old interpreter retained its loaded program,
that hash incorrectly named the new source for an old-code output. No theorem
or census count changed; the source-to-output provenance was invalid.

Repair: confirm the old process has ended, freeze the source, capture its hash
at program entry, and reject publication if the file hash has changed before
writing the bank or receipt. Recompute the normal and optimized order-nine
banks sequentially under the final source, compare their bytes and their
order-eight prefixes, and retain only one deterministic gzip bank. The stale
outputs are superseded. The final receipts and independent audit control the
published state, not this interrupted-run account.

Operational lesson: a wrapper's interrupted status is not proof its child
process has stopped; final source hashing alone is not a loaded-code pin.
