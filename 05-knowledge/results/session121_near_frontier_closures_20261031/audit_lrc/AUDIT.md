# Independent audit: bounded ten-core, three-tail completion

## Analytic verdict: PASS

The conductor in `../lrc/LRC.md` T1 is valid. For an arbitrary interval
of length `ell`, each complete period of speed v contributes bad measure
`2r/v`. The remaining piece, shorter than one period, contributes at most
`2r/v`, even when its phase crosses the periodic seam. Thus the total is
strictly below `2r*ell+2r/v`. When the residual is empty, strictness follows
from the unused positive additive term; when nonempty, it follows from the
strictly shorter length of the full periods. There is no alignment hypothesis.

On a length `1/u_1` interval, the first tail contributes exactly `2r/u_1`.
The remaining k−1 estimates are strict, so the union has measure strictly
below `(4k−2)r/u_1`. This proves positive-measure success including
`r=1/(4k−2)`. Repeated speeds cause no problem for the union bound.

T2 is exhaustive: order u≤v≤w, use the triple conductor for u≥B, the
pair conductor for v≥V_u in each remaining u branch, and the one-tail
conductor for w≥T_uv in each remaining pair branch. Every other triple
lies in an explicitly enumerated leaf range. Empty ranges (T_uv≤v or
V_u≤u) are legitimate because their full feasible ordered domain is already
covered by the corresponding conductor. All widths must be positive;
the checker explicitly rejects zero widths. A closed interval of width
`2r/w` cannot be contained in a single open bad component of speed w,
so the one-tail threshold includes equality and can yield only endpoints.

## Independent computational method

`check.py` imports no producer or copied source module. It constructs every
single-speed full safe comb using `Fraction`, intersects by an independent
two-pointer closed-interval sweep, and merges touching components. It
reconstructs each base cover, every first-attachment cover, every
second-attachment cover, and every finite third-attachment cover. It checks
exact widths and ceilings, all ordered branch ranges without omissions or
duplicates, and every successful leaf against the original speed list.
It checks the census against all combinations of ten members of 1,…,13.

Controls include the marginal-acceptance hostile: at radius1/4 the core
{1,2} separately accepts 3 and12 but rejects their joint attachment.
Closed singleton preservation/rejection and a one-tail threshold attained
only at its two endpoints are tested. The conductor is tested at its exact
radius threshold for k=2,3,4, with nonaligned intervals and repeated tails.
These controls supplement, not replace, the proof.

## Scope

The result concerns exactly the 286 ten-element subsets of {1,…,13}, each
with every triple of positive integer added speeds at radius1/14. Repeats
and core overlaps are included. It is not unrestricted LRC(14), nor a
four-arbitrary-tail family theorem, nor a maximum-radius computation.

## Execution receipts

`result.json` and `result.optimized.json` are generated by normal and `-O`
Python. Their successful stable summaries must match byte for byte. Each
records the SHA256 of the exact full producer receipt audited. Completion
counts and final status are reported in those files; no partial run is a
certificate.

Reproduce from repository packet layout, passing the full receipt path:

    python3 check.py path/to/triple_receipt.json
    python3 -O check.py path/to/triple_receipt.json

The full receipt can be regenerated by `triple_certificate.py`; a compact
per-core summary is not substituted as the input of this exhaustive audit.

`mutation_controls.py` checks five malformed certificates: missing core,
missing first branch, missing second branch, incorrect second width, and
incorrect final cutoff. All are rejected before any full replay is needed.
Normal and optimized mutation receipts agree.

`compact_binding.py` separately checks all 286 compact core records and
branch-tree hashes against the full ledger, including exact core endpoint
lists, counters, and the full-ledger hash. It is only an integrity check;
the complete independent replay is still `check.py`.

### Final completed result

**PASS in normal and optimized Python, byte-identical summaries.** Exhaustive
replay covered 286 cores, 13,693 first branches, 574,336 second branches,
and 67,585 finite third-tail leaves. Maximum triple/pair/single cutoffs were
137/314/82. All 1,827 conductor boundary controls and six hostile/endpoint
controls passed. Both modes also rejected all five mutated receipts and
verified all 286 compact tree bindings.

Audited full-ledger SHA256:
`5fc90cf7308ec97660136047e80ee2aa956a0ad95722a3f5adc38bcf1a701ea0`.

All computation uses exact rational arithmetic and explicit failures rather
than removable assertions. No missing branches, rejected finite leaf, or
zero-width required branch was found. The analytic proof plus this complete
finite audit certifies the stated bounded-core infinite family.

### Reproduction from compact publication

The 12 MB full ledger need not be published. With this directory named
`audit_lrc` alongside the producer `lrc` directory, run from their parent:

    python3 lrc/triple_certificate.py --output /tmp/lrc-full.json
    python3 audit_lrc/check.py /tmp/lrc-full.json > /tmp/audit-normal.json
    python3 -O audit_lrc/check.py /tmp/lrc-full.json > /tmp/audit-optimized.json
    cmp /tmp/audit-normal.json /tmp/audit-optimized.json
    python3 audit_lrc/compact_binding.py /tmp/lrc-full.json lrc/triple_compact_receipt.json
    python3 audit_lrc/mutation_controls.py /tmp/lrc-full.json

Both subsidiary checkers also accept `python3 -O`. The independent full
replay takes the regenerated JSON as a positional path; no absolute
workspace location, current timestamp, or output path enters its summary.
The published summary binds this regenerated ledger by SHA256. The producer
must finish regeneration before the audit is run; a compact summary alone
is deliberately not accepted as a full ledger.
