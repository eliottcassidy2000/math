# Three marked vertices: exact transfer and a fixed radix-16 obstruction

## Scope and outcome

A tournament consists of three fixed marked vertices (the **ears**) and an
ordered transitive spine. A spine letter `a in {0,...,7}` has bit i equal to 1
when ear i beats the newly appended spine vertex. Earlier spine vertices beat
later ones. The fixed ear core is either transitive or a directed triangle.
These are the two isomorphism types of three-vertex tournaments.

**Theorem.** For either core, no actual seed of Hamiltonian-path count H>1
supports a fixed complete length-two balanced radix-16 compiler: a fixed bank
of two-letter append templates realizing all sixteen recurrences

    H -> 16 H + d,   d in {-15,-13,...,15},

at every descendant generated by that bank.

This is a restriction on this constructor architecture, **not** an exclusion
of any tournament path count. It does not settle the global odd spectrum,
and it does not exclude phase-dependent physical template banks that need
not permit an individual template to repeat indefinitely.

The initial proof uses combinatorial growth to remove 37 templates, then
exact rational separating certificates to remove fourteen more, leaving only
thirteen templates for sixteen distinct outputs. A stronger follow-up below
uses cross-order occupancy identities to remove the remaining twelve nonzero
templates. **Only00 survives these necessary conditions, so in fact even a
fixed bank of two distinct balanced radix-16 digit actions is impossible.**
All certificate inequalities are checked with standard-library rational
arithmetic; a floating LP only proposed them.

## 1. Exact 324-state transfer

Fix one of the six orders `(a,b,c)` in which the ears occur along a Hamiltonian
path. The spine is partitioned into four increasing subsequences: prefix,
first middle run, second middle run, suffix. Each spine vertex belongs to
exactly one run.

The prefix has three states: empty, last vertex beats a, last vertex loses
to a. Each middle has three states: empty, valid start and last vertex beats
the next ear, valid start and last vertex loses to the next ear. The suffix
has two states: empty, valid start. A middle may start only when its preceding
ear beats its first vertex; similarly for the suffix. New vertices overwrite
a nonempty run's endpoint status. Thus there are

    6 * 3 * 3 * 3 * 2 = 324

states. Prefix acceptance is empty or good endpoint. Each middle accepts a
good endpoint, or emptiness when the corresponding consecutive ear arc goes
forward. Both suffix states accept. Summing the six ear-order blocks counts
every directed Hamiltonian vertex-word path exactly once.

Let M_a be the nonnegative integer transfer, v the current state, and c the
acceptance row. For every actual state v >= 0, each order has the normalization

    ell_o(v) = sum_p v[o,p,0,0,0] = 1.                 (1)

There is exactly one assignment putting every spine vertex into the prefix;
other assignments cannot return their middle/suffix runs to empty. In fact
ell_o M_a = ell_o for every letter.

The independently implemented `audit/audit.py` checks this transfer against
adjacency/subset DP for all4,681 words of lengths0..4 in each core (9,362
comparisons), and verifies every prefix-normalization invariant. Normal and
optimized Python receipts agree. The original exploratory implementation
also checked200 longer random instances; those are not needed or shipped
as part of this curated proof packet.

## 2. Common spectral filtration

The local prefix reset has a common triangular flag with diagonal `(0,0,1)`.
Each middle has diagonal `(0,1,0)` on the flag
`<good-bad> < <good,bad> < all`; the suffix has diagonal `(1,0)` on
`<started> < all`. Each letter's transfer is the Kronecker sum of these four
local operators. Thus per-order multiplicities are the coefficients of

    (2+t)^3 (1+t) = 8 + 20t + 18t^2 + 7t^3 + t^4.

For a nonempty word of length L, common triangularity gives characteristic
polynomial on the full state space

    z^48 (z-1)^120 (z-2^L)^108 (z-3^L)^42 (z-4^L)^6.

No diagonalizability claim is made. `audit/spectral_and_example.py` independently checks the common exact
local triangular flags for all32 letter/run configurations; the Kronecker-sum
argument then gives every order block.

## 3. Growth first reduces 64 templates to 27

If a two-letter word `(a,b)` has `a & b != 0`, some ear beats every new vertex
in every repetition of that word. In each possible ear order, the run
immediately before that ear can contain no appended vertex: its last vertex
would have to beat the ear. For a fixed old seed of spine length n, at most
three runs are available per appended vertex, giving the simple bound

    H(seed (ab)^k) <= 6 * 4^n * 3^(2k).

An indefinitely repeated balanced radix-16 recurrence would instead give

    H_k = 16^k (H_0 + d/15) - d/15
        >= 16^k (H_0-1) + 1,

contradicting that upper bound when H_0>1 and |d|<=15.

Hence every template in a fixed bank must have disjoint set bits:
`a & b = 0`. Each ear bit column is then one of 00,01,10, so exactly `3^3=27`
templates remain. The analogous one-letter radix-4 argument leaves only
letter000 and already excludes a complete four-template bank.

## 4. Exact rational exclusion of fourteen surviving templates

For a two-letter template let M=M_b M_a and define

    R = c(M-I)(M-16I) = c M^2 - 17 c M + 16 c.

If `c M^(k+1) v = 16 c M^k v + d` for all k>=0, then

    R M^j v = 0   for all j>=0.                     (2)

The supplied certificates combine finitely many rows in (2), rescaled by
positive integer gcds, with the six rows ell_o from (1). For each certificate
there are rational multipliers lambda_j and alpha_o such that the row

    G = sum_j lambda_j R_j + sum_o alpha_o ell_o

is coordinatewise nonnegative, while `sum_o alpha_o < 0`. Here each R_j is a
positive scalar multiple of R M^j. For an actual state satisfying (2),

    0 <= Gv = sum_o alpha_o < 0,

which is impossible. These fourteen exclusions do **not** use a bound on d,
a lower bound on H, integrality of v, or actual-state constraints other than
v>=0 and the six prefix normalizations.

For both core types the certificate covers precisely the eligible words with
odd popcount(a|b):

    01 02 04 07 10 16 20 25 34 40 43 52 61 70.

This is six words of union support size one, and eight words of union support
size three. The thirteen not excluded by these certificates are

    00 03 05 06 12 14 21 24 30 41 42 50 60.

We do not claim those thirteen support a recurrence. Their survival is only
a limitation of this certificate relaxation. Since thirteen is less than
sixteen, however, it already proves the stated fixed-bank theorem.

`code/verify_farkas.py` independently rebuilds the 324-state transfer without
importing the discovery implementation, and checks all 28 certificates, all
9,072 coordinate inequalities, and the strict negative constants. Four
hostile certificate mutations are rejected. It uses only the Python standard
library and gives identical normal/optimized receipts.

## 5. Cross-order occupancy strengthens thirteen survivors to one

Forget the good/bad endpoint flags. Retain only which of the four runs are
nonempty, labeling the prefix by P and each nonprefix run by the ear that must
beat its first vertex. This gives sixteen occupancy masks. The combinatorial
assignment conditions are now independent of ear order: P can always start,
and the run labeled by ear a can start exactly when the current letter has
bit a equal to1. Already nonempty runs can always accept another vertex.

Thus all six ear-order blocks have the same sixteen occupancy totals, after
this relabeling. Subtracting the reference-order totals gives eighty exact
linear relations on every actual state. A completely explicit sixteen-state
quotient proves their invariance: on occupancy mask S, assigning a new vertex
to P sends S to `S union {P}`, and assigning it to run a sends S to
`S union {a}` if a is already in S or the letter has bit a equal to1.

The checker `code/verify_occupancy_farkas.py` verifies this quotient for every
order and letter: 768 row identities, or 248,832 exact coordinate equalities.
It also checks the common empty-spine initial values, establishing the eighty
relations by induction for all reachable states, not just searched seeds.

Adding these relations (right-hand side zero) to the previous Farkas
relaxation gives twelve additional template exclusions for each core:

    03 05 06 12 14 21 24 30 41 42 50 60.

Their union support has size two. The twenty-four new certificates have
7,776 nonnegative rational coordinate inequalities and strictly negative
normalization constants. All are verified independently of the LP, with four
hostile mutations rejected. Normal and optimized receipts agree.

Together, the two certificate banks exclude **every nonzero eligible
pair**. Only00 remains unexcluded; no existence claim is made for00. The
fixed complete-bank theorem follows with much room to spare, since a single
physical template cannot yield two different digit outputs at one state.

## 6. Uniform formula for complementary templates

There is a particularly simple exact identity behind the eight templates
with `a xor b = 7`. For either core and every one of these templates,

    c M(M-I)^3(M-4I)^3(M-9I)^2(M-16I) = 3840 sum_o ell_o.     (3)

The standard-library checker `code/verify_complement_identity.py` verifies all
sixteen core/template identities, comprising 5,184 integer coordinate
equalities. It also rejects two hostile mutations. Normal and optimized
receipts agree. This strengthens the corresponding eight Farkas exclusions:
positivity is unnecessary, only the normalizations (1) are used.

Let `H_k = H(seed w^k)`, and let E denote the forward shift in k. On every
actual seed, (3) becomes the seed-independent inhomogeneous recurrence

    E(E-1)^3(E-4)^3(E-9)^2(E-16) H_k = 23040.

Multiplying by `(E-1)` gives a homogeneous recurrence. Consequently, for
k>=1 there are rational seed/template-dependent coefficients with

    H_k = A 16^k + (B+Ck) 9^k + (D+Ek+Fk^2) 4^k
          + (4/27)k^3 + Gk^2 + Jk + K.                    (4)

Here the symbol E inside `(D+Ek+Fk^2)` denotes a scalar coefficient, not the
shift operator. The exceptional k=0 coordinate may contain the zero-eigenvalue
transient. Most importantly, the coefficient of k^3 is **always 4/27**,
independent of the seed, core, and complementary template. Indeed, the
remaining polynomial factors evaluated at the eigenvalue1 give

    1 * (1-4)^3 * (1-9)^2 * (1-16) = 25920,

and `(E-1)^3 k^3 = 6`; hence the coefficient is
`23040/(6*25920)=4/27`.

Thus these repeated constructions necessarily retain a nonzero cubic
polynomial contribution even while their dominant growth can be exponential.
A pure affine radix-16 recurrence has only a constant1-mode, and is
incompatible with this uniform cubic term. Formula (4) is a general formula
for this construction family, not a solution of the overall spectrum problem.

## 7. Finite search that motivated the certificate (not the proof)

Historical exploratory census (not used by the proof, not included in the
curated replay, and not independently rerun): all2,396,745 spine words of
lengths0..7 were enumerated for each core.
Among actual H>1 seeds:

* One-step coverage of `{16H-15,16H-13,...,16H+15}` never exceeded 11/16 for
  the transitive core or 12/16 for the cyclic core.
* Adding the necessary self-repeat condition `H(vww)=17H(vw)-16H(v)` left
  at most one distinct balanced digit per seed.
* Only sixteen seed/template occurrences survived that second-iterate test;
  all sixteen failed the third iterate.

For example the cyclic core with seed35751 and template70 has

    H_0=215, H_1=3443, H_2=55091, H_3=878159.

The first two steps mimic `H -> 16H+3`, but the third is smaller than its
predicted value by3300. This is a concrete warning against promoting a small
number of successful iterations to an invariant constructor.

## Reproduction

From any working directory, run the bundle's absolute or relative script path:

```sh
python /path/to/this/bundle/verify_all.py
```

This runs every producer certificate check and both independent audit scripts,
each normally and with `-O`, and compares their byte-identical output to the
bundled receipts. Python's standard library suffices. The replay is read-only.
Use `--write-receipts` only when intentionally regenerating receipt files.
No LP solver, symbolic package, discovery code, generated header, original
workspace, network access, or exploratory seed enumeration is required.

## Implication for the research program

Adding a third ear increases the natural maximal growth from three to four,
but does not by itself make a complete stateless positional compiler work:
even the first length where combinatorial template counts permit enough
branches is ruled out by reachable-state normalization certificates. A
productive next model should change a genuine hypothesis—e.g. nonmaximal
radix, state-dependent physical templates, longer macros, or changing the
carrier—not merely seed enumeration in this excluded bank architecture.
